## Executive Summary

Wazuh is a mature, open-source security platform that unifies **XDR and SIEM** capabilities for endpoints, cloud workloads, containers, and network devices. Its architecture pairs a multi-platform **agent** (or agentless syslog) with central **server**, **indexer**, and **dashboard** components ([Wazuh documentation](https://documentation.wazuh.com/current/getting-started/architecture.html)). With **~16,000 GitHub stars**, creation dating to **2015**, and active commits through June 2026 ([GitHub API](https://github.com/wazuh/wazuh)), Wazuh is one of the most widely deployed open-source alternatives to commercial SIEM/XDR stacks. Differentiation versus Splunk, Elastic Security, and cloud-native SIEMs is primarily **cost and openness** (self-hosted, no per-GB license for the open-source core), **breadth of built-in modules** (FIM, vulnerability detection, SCA, active response), and **unified agent** model—not a novel detection paradigm.

## Landscape Context

### The problem

Organizations need centralized threat detection, compliance, and incident response across hybrid infrastructure without Splunk-style licensing costs or vendor lock-in. Open-source SIEM/XDR fills gaps for mid-market, MSSPs, and security-mature teams willing to operate their own stack.

### Incumbents

| Incumbent | Approach | Wazuh contrast |
|-----------|----------|----------------|
| Splunk Enterprise Security | Commercial SIEM, per-GB pricing | OSS core; self-managed indexing |
| Elastic Security | Elastic Stack-native SIEM | Wazuh bundles agent + rules + UI; historically Elastic integration |
| Microsoft Sentinel | Cloud SIEM | Wazuh strong on-prem/hybrid agent control |
| OSSEC (legacy) | HIDS fork ancestor | Wazuh is modern fork/successor with XDR scope |

## What It Is

[Wazuh GitHub README](https://github.com/wazuh/wazuh/blob/master/README.md) describes a **free and open source platform** for threat prevention, detection, and response across on-prem, virtualized, container, and cloud environments.

**Core components** ([architecture docs](https://documentation.wazuh.com/current/getting-started/architecture.html)):

| Component | Role |
|-----------|------|
| **Wazuh agent** | Endpoint data collection, prevention/detection on monitored systems |
| **Wazuh server** | Analysis engine, decoders, rules, agent management, API (port 55000) |
| **Wazuh indexer** | Search/index storage for alerts (OpenSearch-derived) |
| **Wazuh dashboard** | Visualization, configuration, alert triage |

**Deployment patterns:** all-in-one, single-node, multi-node cluster for scale and HA ([documentation](https://documentation.wazuh.com/current/getting-started/architecture.html)).

**Agentless:** Syslog/SSH from firewalls, switches, routers when agents cannot be installed.

## Evidence-Backed Deep Dive

### Capabilities (documented)

From [README](https://github.com/wazuh/wazuh/blob/master/README.md) and [platform overview](https://wazuh.com/platform/overview/):

- **Intrusion detection** — rootkit/malware/anomaly detection on agents; signature-based server analysis
- **Log analysis** — OS/app logs forwarded to manager; rule-based alerting
- **File integrity monitoring (FIM)** — content, permissions, ownership changes
- **Vulnerability detection** — inventory correlated against CVE databases
- **Configuration assessment (SCA)** — policy/hardening compliance checks
- **Incident response** — active responses (e.g., block IP, disable account)
- **Threat hunting** — log retention, indexing, querying for retrospective investigation
- **Container security** — Docker engine integration
- **Cloud** — AWS, Azure, GCP, Microsoft 365, GitHub monitoring (vendor docs/site)
- **Compliance** — PCI DSS and other frameworks via FIM/SCA/vuln modules

### Architecture & data flow

1. Agents send events to server **TCP 1514** (AES-encrypted by default) ([architecture](https://documentation.wazuh.com/current/getting-started/architecture.html))
2. Server analyzes via decoders + rules (Wazuh Analysis engine)
3. Filebeat ships alerts to indexer **9200/TLS**
4. Dashboard queries indexer and server API

**Wazuh CTI** — public vulnerability intelligence feed integrated with vuln detection module ([architecture](https://documentation.wazuh.com/current/getting-started/architecture.html)).

## Key Findings

- Wazuh is a **production-grade open-source XDR/SIEM** with agent + server + indexer + dashboard architecture documented in official docs ([architecture](https://documentation.wazuh.com/current/getting-started/architecture.html)).
- Built-in modules cover **FIM, vulnerability detection, SCA, active response, and container security** without requiring separate point products ([README](https://github.com/wazuh/wazuh/blob/master/README.md)).
- **~16k GitHub stars** and continuous 2026 development indicate sustained community and vendor investment ([GitHub](https://github.com/wazuh/wazuh)).
- Differentiation from commercial SIEM is primarily **economic and operational control** (self-hosted OSS), not proprietary ML detection marketing ([wazuh.com](https://wazuh.com/platform/overview/)).
- Agentless **syslog** support enables partial network-device coverage where agents are impractical ([architecture](https://documentation.wazuh.com/current/getting-started/architecture.html)).

## Differentiation Analysis

| Dimension | Wazuh | Splunk ES | Elastic Security | CrowdStrike Falcon |
|-----------|-------|-----------|------------------|-------------------|
| License | Open-source core (GPL family) | Commercial | Elastic License / SSPL | Commercial SaaS |
| Deployment | Self-hosted primary | Self/cloud | Self/cloud | Cloud-first agent |
| Data model | Wazuh indexer (OpenSearch) | Splunk proprietary | Elasticsearch | Vendor cloud |
| Endpoint agent | Multi-OS Wazuh agent | Add-ons/partners | Elastic Agent/Defend | Falcon sensor |
| Rule ecosystem | Wazuh rules + decoders | SPL, ES notables | KQL detections | IOA/IOC cloud |
| TCO | Lower license cost; higher ops labor | High ingest licensing | Moderate | Per-endpoint subscription |

### Novel vs incremental

Wazuh **consolidates** classic HIDS/SIEM functions (OSSEC lineage) with modern XDR marketing and cloud modules—it is **incremental architecturally** but **highly differentiated commercially** as a full-stack OSS alternative. It is not agentic-AI-native like Nebulock or Spectrum Security.

### What's genuinely distinctive

- Single OSS project spanning agent, SIEM rules, indexer, and dashboard
- Large global install base and MSSP adoption (community evidence via stars/contributors)
- Wazuh CTI public vulnerability feed integrated into agents

### What is repackaged

- Individual capabilities (FIM, vuln scanning, log analysis) exist in many tools; Wazuh's value is integration and OSS delivery.

## Risks and Open Questions

- **Operational burden:** Self-hosted SIEM at scale requires indexer clustering expertise
- **Detection sophistication:** Rule/decoders vs cloud ML/XDR—teams may still need complementary EDR for advanced threats
- **License complexity:** Not as simple as MIT; commercial use/redistribution needs legal review
- **Elastic relationship:** Historical Elastic Stack integration; roadmap vs native OpenSearch indexer should be verified for new deployments
