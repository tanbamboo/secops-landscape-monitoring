## Executive Summary

AiSOC is a **MIT-licensed, self-hostable AI Security Operations Center** created by maintainer beenuar, first published May 2026 and at **v7.5.0** as of June 2026 ([GitHub](https://github.com/beenuar/AiSOC)). It combines ingest/normalization (OCSF, Kafka), detection (Sigma/YARA/KQL rules, UEBA, fusion), **LangGraph multi-agent investigation**, and SOAR-style response in a single Docker-deployable stack. Its clearest differentiation versus closed-source "AI SOC" vendors is **auditable agent behavior**: an **Investigation Ledger** records every LLM prompt, tool call, and evidence citation, plus a **public CI-gated eval harness** over synthetic incidents ([benchmark docs](https://tryaisoc.com/benchmark)). With **~1,450 GitHub stars** in under two months, it is the fastest-rising open-source entrant in the autonomous SOC space—though production adoption and independent security audits are not yet established.

## Landscape Context

### The problem

Enterprises want AI-assisted SOC triage without sending telemetry to proprietary clouds or accepting black-box agent decisions. Commercial AI SOC products (Dropzone-class) offer capability but limited inspectability.

### Incumbents

| Player | Model | AiSOC contrast |
|--------|-------|----------------|

## What It Is

Per [README](https://github.com/beenuar/AiSOC/blob/main/README.md) and [tryaisoc.com](https://tryaisoc.com/):

- **Single stack:** connectors → ingest (Go, OCSF) → Kafka → fusion/UEBA/rules → AI agents → PostgreSQL/ClickHouse/OpenSearch/Neo4j/Qdrant
- **Agents:** Detect, Triage, Hunt, Respond (LangGraph ~600-line orchestrator)
- **Surface:** FastAPI core, Next.js 14 console, Slack ChatOps, MCP server
- **Purple team:** Atomic Red Team + Caldera integration
- **Deploy:** Docker Compose, Render, Fly.io, one-click install scripts; demo at [tryaisoc.com](https://tryaisoc.com)

**License:** MIT ([GitHub API](https://api.github.com/repos/beenuar/AiSOC)).

## Evidence-Backed Deep Dive

### Architecture

Documented mermaid architecture in README shows:

- **50+ connector targets** (Python), osquery-tls, enrichment (IOC + Shodan)
- **Event spine:** Apache Kafka
- **Detection:** fusion ML, UEBA baselines, Sigma/YARA/KQL, threat intel (TAXII/MISP/OTX)
- **Graph:** Neo4j attack graph at ingest (17 node types per README v7 notes)
- **Storage tier:** PostgreSQL (cases/RLS), ClickHouse (events), OpenSearch, Qdrant (RAG), Redis

### Investigation Ledger & eval harness

1. **Ledger** — durable per-step agent audit trail ([why-open-source](https://tryaisoc.com/why-open-source))
2. **Harness** — 200 incidents / 55 templates; 1,000-alert noise stream for alert-reduction metric; CI gates on `main`/`develop` ([benchmark](https://tryaisoc.com/benchmark))
3. Project explicitly labels substrate gates vs future "wet-eval" with live LLM-as-judge ([benchmark page](https://tryaisoc.com/benchmark))

## Key Findings

- AiSOC is a **full-stack MIT AI SOC** with Kafka spine, multi-database storage, and LangGraph agents—not a thin chat wrapper ([README architecture](https://github.com/beenuar/AiSOC/blob/main/README.md)).
- **Investigation Ledger** provides replayable agent decisions—a differentiator vs closed AI SOC products that do not publish audit trails ([tryaisoc.com/why-open-source](https://tryaisoc.com/why-open-source)).
- **Public eval harness** with synthetic telemetry across 14 log source types enables reproducible substrate regression testing ([benchmark](https://tryaisoc.com/benchmark)).
- README comparison positions AiSOC against Wazuh and Splunk on autonomous investigation, audit trail, and harness transparency ([README comparison table](https://github.com/beenuar/AiSOC/blob/main/README.md)).
- Rapid **community traction** (~1.5k stars in ~8 weeks) indicates strong practitioner interest; enterprise production references not found ([GitHub](https://github.com/beenuar/AiSOC)).

**Novel:** Open, reproducible AI SOC substrate with explicit eval methodology. **Incremental:** Individual components (Sigma, Kafka, LangGraph) are established; value is integration + transparency.

## Risks and Open Questions

- Very young project; single-maintainer concentration risk
- Wet-eval / live LLM accuracy not yet CI-gated per project roadmap
- Operational complexity (Kafka, Neo4j, ClickHouse) vs lighter stacks
- Self-comparison table is author-maintained—not independent benchmark
- No third-party penetration test or SOC 2 for the OSS project itself (governance features documented for operators)
